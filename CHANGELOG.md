# Changelog

All notable changes to ForgeSF are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Nothing has been released yet: there is no installer to download, and the
version in `tauri.conf.json` (0.1.0) marks work in progress. The first entry
below becomes 0.1.0 when the release workflow publishes it.

## [Unreleased]

### Added

- **An org information panel.** Identity, instance and API version from
  `sf org display`, and every governor limit with its headroom from
  `sf limits api display` — fullest first, so a limit at 98% is the first thing
  you see. The org's access token stays in the CLI: every field shown is picked
  by name in Rust.
- **Salesforce-aware "New…".** Apex classes and triggers, LWC and Aura bundles,
  Visualforce pages and components, generated by the CLI's own templates, so
  the `-meta.xml` and API version match the project instead of being rebuilt by
  hand.
- **An Apex test runner.** Run selected classes, all local tests or the whole
  org; read failures with their stack traces; see per-class coverage, and the
  lines the run never reached marked in the editor's gutter.
- **Debug logs.** List and read the org's logs, filter them by category
  (debug, SOQL, DML, errors, limits, callouts), search inside one, and watch
  the org live — which sets up the trace flag for you.
- **A real SOQL editor.** Monaco with SOQL highlighting, and completion built
  from the connected org's own describe, so a custom field is offered the
  moment the org has one. Plus a Tooling API toggle and CSV/JSON export.
- **Manifest tools.** Generate a `package.xml` from what is selected in the
  explorer, then retrieve or deploy through it. Manifests live in `manifest/`,
  where they can be committed and reused.
- **Org Compare.** Retrieve the same manifest from two orgs into scratch
  projects and diff them, reusing the Diff Check engine. Neither org's copy
  touches your workspace.
- **Settings that do something.** Editor font, tab size, wrapping and minimap;
  an `sf` path override that is probed before it is accepted; a default API
  version and deploy test level. All persisted.
- **An activity log.** Deploys, retrieves, test runs and org connections, kept
  across restarts and shown on the Dashboard — which previously read the
  workspace terminal and so knew about none of them.
- **A dependency analyzer.** What uses a component and what it uses, from the
  org's own records, followable one step at a time with a trail of where you
  have been.
- **Deploy jobs that survive a long deployment.** Deploys and validations start
  asynchronously, report progress, can be cancelled, and keep their job id, so a
  deployment that outlasts the wait is still tracked instead of being reported
  as failed. Test levels, component errors, test results and code coverage are
  shown, and past validations can be quick-deployed.
- **Change tracking.** The workspace records a snapshot after each retrieve and
  deploy, so modified, added and deleted files are listed and can be deployed on
  their own.
- **Content search and Quick Open.** A Rust-side search walks the whole project
  (respecting ignore rules) and returns line previews; `Ctrl+P` opens a file by
  name.
- **A real file explorer.** Keyboard navigation, multi-select, drag-and-drop
  moves, copy/paste, Copy Path, Reveal in the OS file manager, and
  Salesforce-aware create, rename and delete that keep `-meta.xml` companions and
  LWC/Aura bundles together.
- **A file watcher**, so changes made outside ForgeSF (a `git checkout`, a
  terminal retrieve) show up without a manual refresh.
- **Login options.** Production, sandbox or a custom My Domain URL, with an
  alias and an optional "set as default", plus a Re-authenticate action on an
  expired org.
- **In-app dialogs, menus and toasts**, replacing `window.confirm` and silent
  `console.error` failures.
- **A streaming terminal** with cancel and command history.
- **Workspace management.** Registered projects can be renamed and removed from
  the status-bar switcher and from Settings; a folder ForgeSF created for an org
  inside its own data can be deleted along with the entry, while a folder you
  picked is only ever forgotten.
- **Release workflow.** Tagged versions build installers for Windows, macOS
  (Intel and Apple silicon) and Linux, and attach them to a draft release.

### Changed

- **The Deployments page says what it deploys.** It always deployed the active
  local workspace; the "source org" only ever fed the metadata list. The page
  now names the workspace and its org, and refuses a target org that does not
  own it without an explicit confirmation.
- **New projects are created at the org's API version** rather than a version
  hard-coded in the app.
- **Metadata listings are cached** for ten minutes and shared between the
  retrieve wizard and the Deployments page, instead of each page starting the
  CLI again for the same answer.
- **Org list paints from cache first**, then refreshes connection status in the
  background, so the app is usable immediately instead of after several seconds.
- **The Rust backend was split** from one 2,800-line file into modules, and
  `Result<_, String>` became a typed error, so the UI can offer the right action
  (re-authenticate, reload) rather than printing a string.
- **Mock surfaces are labelled or gone.** The Plugins page is marked Preview,
  the fake deploy buttons and the fake "Build Package" step were removed, and
  the Dashboard shows real data.
- The standalone Anonymous Apex page was retired; it lives in Developer Tools.

### Fixed

- **The CLI runner deadlocked on any output larger than a pipe buffer** — a few
  dozen rows was enough — and hung until it was killed. Output is now drained as
  it arrives.
- **The editor never loaded offline or in a packaged build**: Monaco was
  configured in a file that was only ever imported as a type, so it fell back to
  a CDN that the app's own CSP blocks.
- **Multi-line queries and large retrieves failed on Windows**, one on the batch
  file argument rules and one on the command-line length limit. Queries go
  through a file, and large selections through a generated manifest.
- **The workspace registry could be silently emptied** by a concurrent read and
  write. Every change now takes a lock and writes atomically, an unreadable file
  is kept as a `.corrupt` backup rather than overwritten, and the parsed
  registry is cached in memory.
- **Switching orgs quickly could leave the editor showing one org's files while
  deploys went to another.** Switches are serialised, stale results are
  discarded, and file, deploy and diff commands name the workspace they act on.
- **The editor could overwrite a binary or deleted file** with an empty buffer.
  Unreadable files open read-only with an explanation, and saves are atomic.
- **Cancel did not work.** Each run has its own token, and on Windows the whole
  process tree is stopped instead of just the `cmd.exe` wrapper, so no `node`
  process is left holding an org's API calls.
- **Diff Check reported every file as local-only** when a retrieve failed for
  any reason, including expired auth. Failures are now reported as failures.
- **Typing in the retrieve overlay's search box moved focus to Close**, so the
  next space or enter closed the overlay.
- Edits typed while a save was in flight were dropped, and closing a file
  without saving kept its edits in Pending Changes.
- Anonymous Apex and the CLI tab ran against production with no confirmation,
  and `sf org display` in the CLI tab ran as `sf sf org display`.
- `Set Default` wrote project-local CLI config into whatever directory the app
  happened to start in, and the Default badge did not move.

### Security

- The webview can no longer ask the CLI to install, link or update plugins,
  which would have run arbitrary npm code.
- Paths are resolved per component with symlinks checked, so a link inside a
  cloned repository cannot reach outside the workspace, and a diff session is
  named by id rather than by a path from the page.
- `'unsafe-eval'` was removed from the content security policy.
- A folder only becomes a workspace after being chosen in the native picker, and
  `sfdx-project.json` is written into a folder you picked only after you agree.
