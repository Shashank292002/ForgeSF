# Roadmap

Where ForgeSF is and what comes next. Anything not listed as shipped is not
built yet, however confidently the README describes the vision.

The order below is deliberate: correctness and safety first, because this app
writes to real Salesforce orgs, then the features that make it worth opening
every day.

## Shipped

- **Org Manager** — connect (production, sandbox or a custom My Domain URL),
  switch, set default, re-authenticate, open in a browser, log out.
- **Workspace** — one folder per org, a virtualised explorer with keyboard
  navigation and multi-select, Monaco with Apex highlighting, content search,
  Quick Open, a streaming terminal, and a file watcher.
- **Metadata retrieve** — a batched wizard with progress, cancel and retry.
- **Developer Tools** — SOQL, SOSL, Anonymous Apex and a CLI tab, with
  org-scoped history and production confirmation prompts.
- **Deployments** — asynchronous deploy and validate jobs with progress, cancel,
  test levels, component and test results, coverage, and persisted history.
- **Diff Check** — compares a local file against the org through a generated
  manifest.

## Next

Everything below has been built. What remains is the Plugin SDK, and the two
items under "Not scheduled".

### Shipped since

- **Org information panel** — `sf org display` plus `sf limits api display`, as
  a panel on each org card: identity, instance, API version, and every governor
  limit with its headroom, fullest first.
- **Salesforce-aware "New…"** — Apex classes and triggers, LWC and Aura bundles,
  Visualforce pages and components, generated by `sf template generate`, so the
  metadata file and API version are the CLI's rather than ForgeSF's guess.
- **Apex test runner** — a Tests view that runs selected classes, all local
  tests or the whole org, with failures and stack traces, per-class coverage,
  and the uncovered lines marked in the editor's gutter.
- **Debug logs** — list, open and filter the org's logs by category, search
  inside one, and watch the org live (which sets up the trace flag for you).
- **SOQL editor** — Monaco with SOQL highlighting and completion built from the
  connected org's own describe, a Tooling API toggle, and CSV/JSON export
  through a native save dialog.
- **Manifest tools** — generate a `package.xml` from what is selected in the
  explorer, then retrieve or deploy through it; manifests live in `manifest/`,
  so they can be committed and shared.
- **Org Compare** — retrieve the same manifest from two orgs into scratch
  projects and diff them, reusing the Diff Check engine. The workspace is not
  touched.
- **Settings** — editor preferences, an `sf` path override that is probed
  before it is accepted, a default API version and test level, all persisted.
- **Activity log** — a record of deploys, retrieves, test runs and org
  connections that survives a restart, feeding the Dashboard.
- **Dependency analyzer** — what uses a component and what it uses, from the
  org's own dependency records, followable a step at a time.

### Plugin SDK

The Plugins page is a labelled preview. The design — capability model, manifest,
API surface and what has to be true before any of it ships — is written up in
[docs/plugin-sdk.md](docs/plugin-sdk.md). Building it comes after that design is
agreed.

## Not scheduled

- **Auto-update.** The release workflow builds installers; updating is a manual
  download. Turning on `tauri-plugin-updater` needs a signing key pair whose
  private half lives in repository secrets and whose public half is committed in
  `tauri.conf.json`.
- **Signed installers.** Until a code-signing certificate exists, macOS needs
  right-click → Open on first launch and Windows SmartScreen shows a warning.
- **Mobile.** ForgeSF is a desktop application. The Android bundle configuration
  was removed because nothing was building it.
